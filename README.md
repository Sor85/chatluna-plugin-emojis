# ChatLuna Emojis

为 ChatLuna v2 提供 Emoji Kitchen 合成：两个 emoji，一张组合图片。

## 功能

- **聊天合成**：支持连写、空格或加号分隔，正确处理变体选择符与 ZWJ 多码点表情。
- **无前缀触发**：可选直接发送两个 emoji 合成，默认关闭，不匹配其他普通消息。
- **组合查找**：优先使用最新版本，正向无结果时自动尝试反向组合。
- **元数据缓存**：首次自动下载，之后使用 ETag / Last-Modified 检查更新；更新失败不破坏已有缓存。
- **镜像支持**：元数据地址、超时、更新间隔和下载大小上限均可配置。

## 安装

在 ChatLuna v2 的插件管理中安装 `chatluna-plugin-emojis` 并启用。

插件依赖宿主的 HTTP、权限和平台命令桥服务，不提供控制台页面。运行环境为 Node.js 24 或更新版本，仅适用于 ChatLuna v2。

首次启动会下载元数据，体积约 105 MiB，实际大小随上游更新而变化。下载完成前合成显示“元数据尚未就绪”。

## 聊天命令

```text
emoji 😀🔥
emoji ❤️ 🔥
emoji 🐱 + 🐶
emoji.update
```

| 命令 | 功能 | 权限等级 |
| --- | --- | --- |
| `emoji <两个 emoji>` | 返回合成图片 | 1 |
| `emoji.update` | 检查并更新元数据 | 3 |

`emoji` 命令是否需要提及机器人或命令前缀，遵循宿主命令设置。

开启 **允许无前缀触发**（`allowWithoutPrefix`）后，可直接发送 `😀🔥`、`❤️ 🔥` 或 `🐱 + 🐶` 合成，无需 `emoji` 前缀。该选项默认关闭；只有完整消息恰好包含两个 emoji 时匹配，普通文字、单个 emoji 和更多 emoji 不触发。

不是任意两个 emoji 都有组合。未收录的组合返回明确提示，不会用其他图片代替。

## 配置

配置页按“触发方式”“元数据更新”“下载与缓存”三组展示。

| 分组 | 配置项 | 键名 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| 触发方式 | 无前缀触发 | `allowWithoutPrefix` | `false` | 允许直接发送两个 emoji 合成，无需 `emoji` 前缀 |
| 元数据更新 | 元数据地址 | `metadataUrl` | 下方上游地址 | 兼容的 HTTP(S) 元数据源，支持自建镜像 |
| 元数据更新 | 自动更新 | `autoUpdate` | `true` | 开启定时更新；无论此项是否开启，启动时均检查一次 |
| 元数据更新 | 更新间隔（秒） | `updateInterval` | `86400` | 更新间隔，单位秒，范围 3600–2592000 |
| 下载与缓存 | 下载超时（毫秒） | `timeout` | `30000` | 单次下载超时，单位毫秒，范围 1000–300000 |
| 下载与缓存 | 下载大小上限（MiB） | `maxMetadataSize` | `128` | 响应体大小上限，单位 MiB，范围 1–256 |
| 下载与缓存 | 缓存目录 | `dataDir` | `data/chatluna/emojis` | 缓存目录，相对当前 ChatLuna 实例目录解析 |

默认元数据源：

```text
https://raw.githubusercontent.com/xsalazar/emoji-kitchen-backend/main/app/metadata.json
```

元数据、源地址与 HTTP 验证头保存在同一个缓存文件，更新校验成功后原子替换。更换元数据源后不会复用旧源的验证头。下载失败、超时、格式错误和缓存写入失败均独立显示，不会误报为“未变更”。

## 网络与使用限制

- Emoji Kitchen 图片来自 Google，图片与元数据遵循各自上游的使用条款；本插件的 MIT 许可证不授予第三方图片的版权。
- 图片以 `www.gstatic.com` 上的 HTTPS 原链接发送。聊天平台和浏览器需要能够访问该域名；离线缓存仅覆盖元数据，不缓存图片。
- 镜像源只能提供相同格式的元数据，图片地址仍须位于 Google Emoji Kitchen 路径内。
- 不包含图片上传、表情包收藏、AI 绘图或自动收集群聊图片。
